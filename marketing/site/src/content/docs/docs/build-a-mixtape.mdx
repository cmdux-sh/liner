Create a local folder for one focused task. Add sources, review the research, then write instructions an AI assistant can follow. Liner calls the folder a Liner Project, or a liner for short, and the research packet inside it a Mixtape.

## Start with your agent

Connect your agent once, then ask it for lasting research.

<CommandSnippet command={`npm install -g linersh
liner agent-skill install claude --yes`} />

Your agent does the research with its own tools, on your account. Liner owns the steps and checks each result. Compile and instruction-file creation use local saved artifacts without new model calls.

The default workspace is `~/liner/projects`. Set `LINER_DIR` to use another location.

## Creation checkpoints

1. **Job Story** states the task, such as “When I am designing native mobile interactions, I want grounded touch guidance, so I can avoid brittle gesture patterns.”
2. **Clarify Job** records the situation, desired outcome, and boundaries before research begins.
3. **Research** discovers and evaluates evidence, writes working artifacts, and proposes draft Sources.
4. **Approve the synthesis.** Your agent stops and shows you `synthesis.md`, which cites its sources. Editing it afterward reopens this approval.
5. **Approve the sources.** Your agent shows the final source list before anything compiles.
6. **Compile** fetches the sources and writes the Mixtape.
7. **Approve the instructions.** Your agent shows `LINER.md` and `SKILL.md` before they're written.

Watch it happen and read the result in the [navigator](/docs/tui/).

## Use the CLI

CLI paths resolve from your shell's working directory. This example creates a Project in your default library.

<CommandSnippet command={`mkdir -p ~/liner/projects
cd ~/liner/projects
liner init mobile-design-foundations`} />

Add sources through the CLI so Liner can assign a stable ID and check for duplicates.

<CommandSnippet command={`liner sources add mobile-design-foundations \
  --type web \
  --url https://developer.apple.com/app-store/review/guidelines/ \
  --note "Use the current review rules as primary evidence." \
  --priority required`} />

Ask your agent to build the research, then approve its proposed Sources and Synthesis.

After reviewing the recipe and synthesis, run a scriptable compile.

<CommandSnippet command="liner compile mobile-design-foundations" />

The compile step writes the research packet.

## Use the result

After compile, give the AI `mixtape/MIXTAPE.md` and access to `mixtape/sources/`. The compiled file contains a synthesis and links to separate source files.

Compile runs after you approve the Sources. Your agent then writes the instruction files once you approve them.

After the instruction files are written, give the AI the whole folder when it can read files. For lighter use, paste `mixtape/MIXTAPE.md` into the conversation. It contains the synthesis and a source index; provide the referenced source files separately when the assistant needs their content.

## Recompile

When evidence changes, use `liner sources add`, `update`, or `replace` so identity and lineage stay intact. Then rebuild the affected corpus and compile.

<CommandSnippet command="liner compile mobile-design-foundations" />

To compile again, run `liner compile` on the folder.
