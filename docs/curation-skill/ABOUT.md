# About Liner

Liner is an open-source toolkit for building curated context bundles — *mixtapes* — that make AI systems more useful within a specific domain.

## The premise

AI tools are bottlenecked on context, not capability. A model can produce better mobile design feedback when it has access to a thoughtful selection of platform conventions, practitioner writing, and contested perspectives than when it's relying on whatever made it into its training data. The same applies to almost any domain: the model improves dramatically when given good context, and the practical problem becomes assembling that context well.

Right now, that work is invisible and manual. People paste transcripts and articles into chats one at a time. They maintain ad-hoc notes. They rebuild the same context bundle from scratch every time they switch tools. Existing platforms solve hosted use cases — NotebookLM and Claude Projects let you upload files into a sandbox — but the resulting artifact is trapped in the platform and can't be shared as a recipe.

Liner treats curation as the work and produces a portable artifact.

## What Liner is

Liner is several things sharing a methodology and a file format:

- **A CLI** for compiling mixtape projects
- **A Go TUI** for the multi-step authoring lifecycle
- **A skill** that runs the methodology inside Claude
- **A planned MCP server** that will expose the same functions to any agent (Claude Code, Codex, Cursor, others)
- **A planned library** of curated mixtapes anyone can clone, fork, or run as-is
- **A methodology** documented in [CURATION.md](./CURATION.md) and applied across all the above

The implemented pieces are independent. The CLI works without the TUI. The skill works without the CLI. The planned MCP server will add an agent-native surface later. Users pick the surface that fits their workflow.

## What a mixtape is

A mixtape is the corpus inside a Liner project folder. In v2 projects it lives under `mixtape/`; legacy root-level mixtape folders remain readable. The corpus contains:

- A **recipe** (`mixtape/tape.yaml`) — the curated list of sources with notes and sections
- A **synthesis** (`mixtape/synthesis.md`) — the curator's distilled understanding of the domain
- **Source content** (`mixtape/sources/`) — extracted text from every source in the recipe
- **Working notes** (`mixtape/working/`) — the methodology's traces: JTBD, capability brief, knowledge map, source roles, evaluation, quality checks
- A **master file** (`mixtape/MIXTAPE.md`) — the consumable artifact, with the synthesis up front and sources referenced by file

The recipe is small, shareable, and recompilable. The full Liner project folder is heavier, self-contained, and ready to hand to an AI session. The two artifacts have different sharing properties and different purposes.

## Who Liner is for

Developers, designers, researchers, and AI-curious power users who feed AI tools a lot of context and want to do it better. The audience overlaps significantly with people who already use the terminal, write Markdown, and have an opinion about how AI tools should work.

Liner is not aimed at users who want a polished hosted product with no setup. NotebookLM is better for that audience. Liner is aimed at people who want a portable, scriptable, forkable workflow they control.

## What makes Liner different

A few decisions that distinguish Liner from adjacent tools:

- **Curation is the work.** The methodology is the product, not an afterthought. Tools that auto-generate context bundles produce mediocre results because they skip the judgment step. Liner is structured around making that judgment easier.
- **Portable artifacts.** Mixtape folders are plain text — YAML and Markdown. They can be edited by hand, generated by tools, shared in repositories, and forked into derivatives. Nothing is locked into a platform.
- **No hosted backend.** Liner doesn't run a service. The CLI runs locally. The planned library will be a static repository. The website is a static site. No accounts, no servers, no infrastructure that can disappear.
- **Two modes, same architecture.** Quick mode runs the methodology automatically; methodology mode runs it with substantive curator involvement. Same files, same format, different intensity. The planned library will accept methodology-mode mixtapes; personal use is whatever the curator wants.
- **Multiple surfaces, one methodology.** The same curation process applies whether the user is in the terminal, in a Claude conversation, or driving an agent. The methodology document is the source of truth; everything else implements it.

## How the pieces fit together

- The **methodology** ([CURATION.md](./CURATION.md)) defines how to curate well.
- The **mixtape format** ([MIXTAPE-FORMAT.md](./MIXTAPE-FORMAT.md)) defines what a mixtape folder contains and how `tape.yaml` is structured.
- The **platform** ([PLATFORM.md](./PLATFORM.md)) defines how the Liner project specifically operates — implemented surfaces, planned surfaces, the future library, the contribution process, and the boundaries.
- The **tools** (CLI, Go TUI, skill, and planned MCP server) implement the methodology and consume the format.

A curator who learns the methodology can apply it with or without Liner's tools. A curator using Liner's tools can produce mixtapes that exist outside the Liner ecosystem. The methodology, the format, and the tools compose without locking into each other.

## Project status

Active development. Published releases are available on npm; the current source targets v1.1.1, with macOS, Linux, and Windows x64 packages, and remains a local release candidate until publish succeeds.
The CLI and Go TUI support `youtube`, `web`, `local_file`, and inert `skill`
Sources, plus opt-in Playwright rendering. Compilation marks Corpus Ready;
Create Operating Layer writes `LINER.md`, root `SKILL.md`, and `liner.yaml` to
mark Project Complete. Supported Project and Source maintenance uses Liner
Core's versioned inspect, plan, apply, refresh, retention, and Change Receipt
contract. The shipped `curating-mixtapes` skill authors the initial corpus; the
optional Codex and Claude Maintenance Adapters delegate to the installed CLI
and do not replace the Project Skill. The public library and MCP server remain
planned. Maintained as a side project — see [PLATFORM.md](./PLATFORM.md).
