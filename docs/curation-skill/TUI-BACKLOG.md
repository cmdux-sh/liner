## Lessons from cli-writer-6 (2026-05-22)

Captured after comparing cli-writer-3 (v0.3 methodology, 15 sources) and cli-writer-6 (v0.4 methodology, 23 sources) on the same JTBD lineage. The v0.4 methodology changes are visibly paying off (sharper JTBD, task-oriented sections, source-kind chips, framing-gap audit firing). The items below are the next layer of methodology, prompt, and UX tightening suggested by what the artifact shows.

### Methodology — unverified content and the verification re-check

- **Auto re-run the perspectives audit at compile time when previously-unverified sources became verified.** v6 kept two YouTube sources (Küber, Pinsker) with curator notes acknowledging transcripts were unfetched at evaluation. By compile time `yt-dlp` produced real transcripts, but the perspectives audit's "unverified does not count" verdict from Phase 5 was never revisited. A `liner verify <folder>` command (or a compile-time hook) could re-check whether unverified perspective slots are now verifiable, and flag the gap closing as a soft signal back to the curator.
- **Curator-added sources should default to a sensible kind and prompt for it before commit.** The new `[+] add own` flow leaves `kind` unset. Either default to `principle` (the synthesis-writing default per `prompts.ts`) or open a four-button kind picker after URL submission. Cheap UX add; saves the curator a tape.yaml edit pass.

### Quality of evaluation — note-quality smell test

- **Add a Phase 5 note-quality smell test.** Notes that read as filler (e.g., "Skim a few command pages to calibrate density and rhythm") aren't earning weight in the consuming AI's loading decisions. A simple rubric — note must (a) cite what to read for, (b) name the bar it sets, (c) flag one limitation or scope boundary — would force the agent to deepen thin notes before shipping. This should be added after the required source-role fit test, not as "Test 6" (that slot is now taken).

### Compile-time fetcher chain

- **Wayback Machine as a fetcher tier between Playwright and the agent-summary fallback.** Cheap, no tokens, returns raw HTML the trafilatura extractor can use — full article instead of summary. Right move when richer fallback content matters for production-quality mixtapes. Discussed in the v6 session; deferred at curator's request because the agent-summary fallback is sufficient for current scope.
- **Source-specific compile retry.** Go Compile now lets the curator select a warning, open the source, or drop the matching source from `tape.yaml` before retrying the full compile. A true source-only retry remains future work if the Python compile core exposes a targeted refetch contract.

### Surface improvements

- **Library cross-reference at JTBD time (deferred — needs library).** When the library exists, surface "mixtapes in your library that match these JTBD keywords" during Phase 1 so the curator can opt to start from a related one and preserve sources/framings that worked.

## Up next (functional — needed to "get everything working")

### Capture yourself / browser extension (next version)

- **Browser extension for authenticated/private sources.** Current safe workflow: the curator opens a paid/authenticated source in their own browser, copies the useful rendered article/body text, and pastes it into Liner's source inbox or saves it under `local-sources/` as a local file. Next version should make this explicit with a browser extension that captures from the already-authenticated browser session only after the user clicks the extension. It should not read Chrome cookies directly, install credentials, or run arbitrary commands.
- **Extension capture contract.** The extension should send a structured capture payload to Liner: title, canonical/current URL, captured_at, selected rendered text or readable rendered HTML, optional screenshot, and `private: true` by default. Liner stores the payload under `local-sources/captured/` and adds a `local_file` source with citation/provenance. Rendered HTML/text is preferred over raw "view source" because modern pages often ship app shells, scripts, hidden content, and cookie banners rather than the article the user sees.
- **Visual capture follow-up.** For pages where images, charts, layout, or UI state matter, add a later `visual_file`/image-aware source path instead of forcing screenshots through the text-only local-file pipeline. The extension can capture screenshots early, but Liner should label them clearly until downstream vision support is first-class.

### Slice 3 — agent integration polish

- **Post-default release guard.** Codex no-custom-source and custom-source now have full Go TUI passes through Quality, Synthesis, Assembly Review, Compile, and Preview; imported compiled projects have live no-refetch preview/share/copy/open-folder evidence; deterministic failure/retry has Go TUI smoke evidence; Claude Framing has scoped Go TUI evidence; and local preflight plus release smoke prove source-tree and clean-consumer packaging with default-Go shim dispatch. Latest local reports: `/tmp/liner-go-live-acceptance/go-tui-preflight-2026-06-14T21-49-23-208Z.md` and `/tmp/liner-go-live-acceptance/go-tui-release-smoke-2026-06-14T21-49-41-044Z.md`. Next acceptance work is repeating preflight/release-smoke from the release or platform-packaging context before publishing broadly.
- **Background-banner concurrent runs.** Current architecture cancels the run when the user navigates away from PhaseRunner. If we want to support "leave the agent working while I edit elsewhere," we need to lift run state to app context and add a hub banner. Not blocking — pause-and-resume is a real product question, not just an implementation one.

### Empirical-test path (now optional, post-0.5.2)

- **Optional empirical-test capture.** The empirical test was removed as a driven TUI phase in 0.5.2 (*compiled = complete*); it now lives as methodology guidance. If we ever want to bring it back as an *opt-in* tool, it could run the same question through two agent sessions (with and without `MIXTAPE.md`) and write the comparison to an artifact — invoked explicitly, never as a step that parks the hub.
