# Source Quality Hierarchy

Use this before Evaluation.

Evaluate every candidate against the JTBD. The question is not "is this famous?" or "is this interesting?" The question is "will the consuming AI do the stated job better if this source is in the mixtape?"

## Strong Sources

- Primary documents: specs, official docs, standards, manuals, foundational papers.
- Dense practitioner material: essays, talks, postmortems, implementation notes, critique with examples.
- Empirical work where the domain has real research.
- Distinctive examples that calibrate taste or show a concrete pattern.

## Weaker Sources

- Shallow listicles.
- Summaries of sources you can include directly.
- Motivational talks with little transferable detail.
- AI-generated articles or generic SEO content.
- Sources that are only related to the topic, not the JTBD.

## Decisions

- `kept`: clear fit, load-bearing, distinctive, or canonical.
- `trimmed`: useful only in a narrower way; keep only if the note explains when to use it.
- `dropped`: redundant, shallow, off-topic, unavailable, or not useful for the JTBD.

For kept and trimmed sources, include a 1-5 rating and a specific rationale. For dropped sources, say why. Avoid generic rationales like "low quality".

## Common Checks

- Are three sources making the same point? Keep the strongest and cut the rest.
- Is one author dominating the corpus? Keep the strongest work and add other voices when the domain needs perspective.
- Are primary sources missing? Search for them before accepting commentary as a substitute.
- Is recency bias creeping in? Newer is not automatically better.
