# Quality Check Tests

Use this before the Quality checks phase.

Read the JTBD, knowledge map, candidate evaluation, and curator notes together. These checks are about the corpus as a whole.

## Redundancy

Are multiple sources doing the same job with the same examples or claims? Keep the strongest one unless the sources represent meaningfully different perspectives.

## Coverage

Does every important knowledge-map section have at least one credible kept source? If not, either backfill the gap or document why that area is out of scope.

## Disagreement

What is the strongest claim the corpus makes? Is there a credible counterposition? If the domain is contested, include the disagreement or explicitly state the mixtape's stance.

## Framing Gap

Is there a whole way of thinking about the JTBD missing from the corpus? Examples: accessibility, security, maintainer perspective, beginner perspective, visual design, legal/regulatory view, international/non-US view.

If the gap matters, recommend returning to Candidate discovery. If the gap is accepted, document it so the synthesis does not silently pretend the corpus is complete.

## Source Kinds

Check whether the kept sources include enough of these roles for the JTBD:

- `reference`: canonical docs, specs, manuals
- `principle`: concepts, models, arguments
- `prescription`: rules, guidelines, checklists
- `example`: concrete cases, specimens, demos

A zero in one category can be fine, but it should be a decision, not an accident.

## Output

Write the checks into `working/04-quality-checks.md`. Include what passed, what failed, and any recommended next action.
