## 2026-10-30 - Make Liner an agent-first research library

Arturo set the direction: Liner becomes a personal library of reusable research that any agent can find and maintain, and the terminal app becomes one optional way in. This is what makes Liner different from one-time deep research, which is thrown away after a single answer. Three choices follow, each taken from the recommended option:

- **The user's own agent does the research.** Core owns the steps and checks each result; the agent does the work with its own tools. This works across Claude, Codex, and other harnesses and keeps Core free of AI calls. The cost is that untrusted pages reach an agent with more tools than today's stripped-down runner, so the protocol must ship a restricted research subagent and route fetching through Liner.
- **Each liner serves one narrow job.** Subject folders holding many jobs would need a new composition model and conflict with the rule that a topic is not a job. Related liners can cite each other instead.
- **The everyday name is "a liner."** It is how Arturo already talks about them, and it reads well in agent suggestions. "Liner Project" stays the formal term in code and specifications. "Container" stays reserved for composition, and "expert" is avoided because Liner rejects persona framing.

Agents suggest a liner and the person decides, in keeping with the 2026-10-19 decision. The library stays at the existing `~/liner/projects` default. The plan is in [Library plan](project/LIBRARY-PLAN.md).

The second build ran some approvals inside `bash -c '...'`. ## 2026-11-05 - How single-source reuse works

This builds the `liner://slug/source` form decided on 2026-11-02. The address is `liner://<slug>/<source-id>`, using the source's id in the other liner's tape, because compiled file names are numbered and change when sources are reordered. Compiling it copies the saved text from that liner's compiled file instead of fetching, adds a `Reused from` line, and puts the original URL (or a local file's citation) in the header, so a synthesis that cites the original address still opens the copy. Reuse isn't cached, so the copy follows the other liner when it recompiles. A source whose saved text is missing or truncated, or that is itself another liner, can't be reused and the error says what to add instead. `liner refresh` compares a reused source with the other liner's saved copy and says to refresh that liner for the live page, or that a local file has no live page. `liner share` warns before packing one that was a local file, because its text travels in the archive. The research step's library check now tells agents to use the `reuse` address from `liner find-sources`.
